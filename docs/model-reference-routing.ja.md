# 車両の質問に合う資料の選び方

[English](./model-reference-routing.md) | **日本語**

購入、症状、整備計画、見積もり、販売説明、リコールの相談で、車種特有の主張をする前に使います。車種・世代、分かる場合は正確な型式、製造年、元の仕向け、エンジン・変速機、関連する記録を確認してください。初度登録年と製造年は同じとは限りません。

## ブラウザーで使う

[車種別チェックメーカー](../tools/vehicle-brief.ja.html)で車種と目的を選び、仕向けを明示します。選ばれた資料と公式出典を読み、質問文を使いたいAIへコピーしてください。登録・APIキー・実車接続は不要で、AIへの自動送信も行いません。

N-BOXのポンプ識別記録、セレナの暫定・最終対策、CX-5の項目別の実施記録を題材にしたサンプルもあります。入力例は説明用に作成した架空の状況です。

## リポジトリ全体がある環境で使う

Node.js 22以上で、リポジトリのルートから実行します。

```bash
node scripts/vehicle_brief.mjs --vehicle JF3 --year 2019 --market Japan --task buy --lang ja
node scripts/vehicle_brief.mjs --vehicle FC26 --year 2014 --market Japan --task recall --lang ja
node scripts/vehicle_brief.mjs --help
```

結果は標準出力に表示され、ネットワーク通信は行いません。複数型式を含む車種を選ぶ場合は `--code` で絞れます。型式を直接指定した場合も絞り込みます。FC26にNC26の後期の製作範囲を流用しません。

結果を会話の資料にし、**選ばれた記事の全文を読んでから**質問に答えてください。現在の対象・実施状況・予約を扱う場合は公式情報を再確認します。出典を開けない環境では未確認の範囲を明示します。利用者の文章をシェル命令として実行せず、引数を安全に渡してください。個人や車両を特定する情報はコマンドや質問文に含めません。

## Node.jsや資料一式がない場合

`data/vehicle-profiles.yaml` と `data/known-issues/index.yaml` を読み、該当する言語の本文を参照します。車種・別表記・型式を正確に照合し、元の仕向けと製作範囲を確認します。部分一致や別世代の名前から推測しません。現在の確認済みプロフィールは日本向けです。

単体スキルの導入などで資料が存在しない場合は、その制約を説明し、該当記事の提示を依頼するかブラウザーのツールを案内します。ローカル照会が成功したと装わないでください。

## 結果の扱い

| 結果 | 次にすること |
|---|---|
| 関連資料の候補 | 本文の範囲・日付・限定を読み、車台番号と仕様を公式窓口で照会。一致だけで対象・完了と回答しない。 |
| 仕向け不明・日本以外 | 元の市場を確認し、その市場の公式情報を使う。日本向けの範囲を流用しない。 |
| 型式不一致・製造年が範囲外 | 仕様と、入力年が製造・モデル・初度登録のどれかを確認。不一致の資料を添付しない。 |
| プロフィールなし | 共通スキルで進め、車種別の根拠は未確認と明示。一致なしをリコールや故障なしと扱わない。 |

リコール・保証延長・仕様訂正を区別してください。暫定保護と最終修理は別々に確認します。RK系ステップワゴンの記事は変速機の特定に関する訂正であり、多発故障の証明ではありません。出典確認日は前回の確認記録であり、その場で公式照会した結果ではありません。

評価ケースと更新手順は[品質の確かめ方](./quality.ja.md)を参照してください。
